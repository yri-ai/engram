Current system

Engram already has Track B data models, dataset validation, a legacy transition-matrix BaselineForecaster, and Track B unit-test conventions.

Proposed design implemented

  • New src/engram/forecasting/ subsystem isolates forecasting protocol, metrics, split logic, canaries, fixtures, and optional baseline ladder.
  • Core harness supports checked-in fixtures or local event input and refuses missing local events rather than weakening the gate.
  • Record-time discipline is enforced by record_time_filter before scoring and by a harness-path canary.
  • Heavy ML deps are optional/lazy so core imports do not require forecast extras.

Data/state model

Canonical rows contain as_of, split, features, feature_provenance, and label.next_bucket. Future-recorded provenance is removed at prediction time.

Alternatives considered

Using ignored local outputs/track_b/events.ndjson only was rejected because Gate 6 must be reproducible from repo state. A checked-in synthetic fixture is used for deterministic CI-safe verification.
