Goal

Build Engram’s prediction component around a bitemporal probabilistic forecasting kernel, not a RAG-centered app.

The system must answer: Given only what Engram knew at timestamp T, what probability should it assign to outcome Y by horizon H, and why?

Input Request

User requested: Run the existing-app workflow on engram.

Based on the immediately preceding research/design context, the target change is interpreted as:

Build the Temporal Forecasting Kernel around forecast contracts, as-of evidence state reconstruction, structured forecaster protocols, immutable forecast runs, resolution, proper scoring, and calibration reporting. Evidence lookup is plumbing; the product thesis is time-indexed belief formation and auditability.

Acceptance Criteria

IDCriterion
AC1Forecast contracts exist for binary and closed branch questions with mandatory forecast_as_of, horizon, allowed outcomes, and resolution criteria.
AC2Forecast runs are immutable. Reruns create new run IDs and preserve exact model/protocol/evidence references.
AC3An AsOfEvidenceCompiler reconstructs evidence known at forecast time using record-time filters and preserves valid-time, supersession, contradiction, and provenance metadata.
AC4Leakage tests prove future-recorded evidence, resolution evidence, and post-hoc derived facts are excluded from historical forecasts.
AC5Structured forecaster protocol produces probability distributions over binary or closed branch outcomes; probabilities validate and sum to 1.
AC6Forecast runs store evidence IDs and rationale; rationale text alone is not accepted as provenance.
AC7Resolution and score reports support binary Brier, multiclass Brier, log score, top-k accuracy where applicable, and calibration buckets with low-sample warnings.
AC8CLI/service surface allows creating questions, compiling as-of dossiers, running forecasts, resolving outcomes, and scoring stored runs.
AC9Implementation remains deterministic for cutoff enforcement, snapshot reconstruction, validation, immutability, resolution storage, scoring, and calibration reporting.
AC10Verification passes targeted unit tests, uv run mypy src, targeted uv run ruff check, and relevant smoke tests.

Non-Goals for This Workflow

  • No temporal graph neural network training.
  • No TGL-LLM graph tokenization/fine-tuning.
  • No claims of calibrated performance before enough resolved forecasts exist.
  • No generic public-event forecasting bot as the core product.
  • No vector-only or RAG-centered architecture.
  • No continuous numeric forecasting across arbitrary domains in the MVP.
  • No autonomous web-search forecaster as the core product.
